# ZMK Keyboard Configuration

ZMK firmware config repo for a personal ortholinear keyboard family. All boards run the same keymap design. Load the `zmk-keymap-builder` skill for detailed layer specs and workflows.

## Keymap Philosophy

- **Reference design:** `config/helix.keymap` (5-row split 50%) is the gold standard.
- **4-row parity rule:** The bottom 4 rows of every board are physically identical in function and position — same keys, same layers, same bindings. This holds whether the board is 40% or 50%, split or one-piece.
- **50% bonus row:** The top row on 50% boards gives direct access to numbers (Layer 0) and F-keys (Layer 1). On 40% boards those functions are remapped onto Layer 1 row 1 (F-keys) and Layer 2 row 1 (numbers). The bonus row on 50% boards is `&trans` on Layers 2 and 3.
- **Simple bindings only:** `&kp`, `&mo`, `&bt`, `&out`, `&soft_off` — no hold-tap, combos, or macros unless explicitly requested.

## Layer Design Notes

- **LOWER** (`&mo LOWER`, home row col 0): symbols, F-keys (50% bonus row), media/nav/brightness controls.
- **RAISE** (`&mo RAISE`, bottom row col 7): number row substitute (40%), numpad. No BT/output bindings.
- **ADJUST** (hold LOWER + RAISE simultaneously): F1–F12 on the top row, BT profile management on the ZXCV row, `&soft_off` + `OUT_BLE`/`OUT_USB` on the bottom row. Identical layout on all boards.
- **Power / sleep:** All wireless boards: `CONFIG_ZMK_SLEEP=y` (auto deep sleep after 3h), `CONFIG_ZMK_PM_SOFT_OFF=y`. `&soft_off` on ADJUST bottom row col 0 with `hold-time-ms = <500>`. Any keypress wakes from sleep/soft-off. Planck is USB-only — no sleep config, no soft-off.
- **Reset / bootloader:** All keyboards have a physically accessible reset button. Single tap = reset, double tap = bootloader (DFU). No keymap bindings needed or used for this.
- **No stuck layers:** all layer keys use `&mo` (momentary). No `&to`, `&tog`, or `&sl`.

## Active Profiles

| Shield/Board | Form | Type | Custom shield? |
|---|---|---|---|
| `helix` | 5-row split 50% | Reference | No (upstream ZMK) |
| `helix_4row` | 4-row split 40% | Planck-like | Yes — `boards/shields/helix_4row/` |
| `blank_slate` | 4-row one-piece 40% | Wireless, Planck-compatible | No (via `blank-slate-zmk-module`) |
| `planck` | 4-row one-piece 40% | USB-only legacy | No (upstream ZMK) |

Each profile has `config/<name>.conf` and `config/<name>.keymap`. Build targets are in `build.yaml`.

## Custom Shield Pattern

When a board needs a non-standard matrix (e.g. `helix_4row`), create a custom shield under `boards/shields/<name>/` containing `Kconfig.shield`, `<name>.dtsi`, and `<name>_left.overlay` / `<name>_right.overlay`.

Upstream shields (helix, planck) are provided by ZMK. `blank_slate` comes from `blank-slate-zmk-module` (petejohanson, `core-zephyr-hwmv2-update` branch). A local board extension at `boards/lpgalaxy/blank_slate/` adds the `zmk` variant: `board.yml` (extend + zmk variant), `blank_slate_nrf52840_zmk.dts` (includes base DTS via `#include <blank_slate.dts>`), and `Kconfig.blank_slate` (selects `ZMK_BOARD_COMPAT` for the zmk variant).

## Workflow Rules

1. Any new build target must be added to `build.yaml` (this drives the GitHub Actions matrix).
2. When modifying any keymap layer, audit parity across all active profiles and port changes consistently.
3. Board ID syntax (ZMK Zephyr 4.1): all boards use `//zmk` — `nice_nano//zmk`, `planck//zmk`, `blank_slate//zmk`. The `blank_slate//zmk` variant is defined by a local board extension at `boards/lpgalaxy/blank_slate/` because the upstream module doesn't define it.
4. Standard wireless `.conf`:
   ```properties
   CONFIG_BT_CTLR_TX_PWR_PLUS_8=y
   CONFIG_USB_HID_POLL_INTERVAL_MS=1
   CONFIG_ZMK_SLEEP=y
   CONFIG_ZMK_IDLE_SLEEP_TIMEOUT=10800000
   CONFIG_ZMK_PM_SOFT_OFF=y
   ```
   Note: `CONFIG_ZMK_BOARD_COMPAT` is a hidden Kconfig symbol set by board definitions. The blank_slate module board doesn't set it, so the CI compat check emits a **warning** (non-fatal). Do not attempt to set it in user `.conf` (hidden symbol, will error) or via a `boards/lpgalaxy/blank_slate/` extension (creates a spurious `zmk` qualifier that makes the CI check fatal instead).
