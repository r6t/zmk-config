# ZMK Keyboard Configuration

ZMK firmware config repo for a personal ortholinear keyboard family. All boards run the same keymap design. Load the `zmk-keymap-builder` skill for detailed layer specs and workflows.

## Keymap Philosophy

- **Reference design:** `config/helix.keymap` (5-row split 50%) is the gold standard.
- **4-row parity rule:** The bottom 4 rows of every board are physically identical in function and position — same keys, same layers, same bindings. This holds whether the board is 40% or 50%, split or one-piece.
- **50% bonus row:** The top row on 50% boards gives direct access to numbers (Layer 0) and F-keys (Layer 1). On 40% boards those functions are remapped onto Layer 1 row 1 (F-keys) and Layer 2 row 1 (numbers). The bonus row on 50% boards is `&trans` on Layers 2 and 3.
- **Simple bindings only:** `&kp`, `&mo`, `&bt`, `&out`, `&soft_off` — no hold-tap, combos, or macros unless explicitly requested.

## Layer Design Notes

- **LOWER** (`&mo LOWER`, home row col 0): symbols, F-keys (50% bonus row), media/nav/brightness controls.
- **RAISE** (`&mo RAISE`, bottom row col 7): number row substitute (40%), numpad. No BT/output bindings.
- **ADJUST** (hold LOWER + RAISE simultaneously): F1–F12 on the top row (row 1 on 40%, row 2 on 50%), BT profile management (`BT_SEL`, `BT_DISC`, `BT_CLR`) on the ZXCV row, `OUT_BLE`/`OUT_USB` and `&soft_off` (power off) on the bottom row. Identical functional layout on all boards. The conditional layer fires regardless of which order LOWER/RAISE are pressed.
- **Power / sleep:** wireless boards use `CONFIG_ZMK_SLEEP=y` (auto deep sleep after 3h), `CONFIG_ZMK_PM_SOFT_OFF=y` (explicit off key). No `CONFIG_ZMK_IDLE_TIMEOUT` — no displays or RGB so idle state is a no-op. `&soft_off` is on ADJUST bottom row col 0 with `hold-time-ms = <500>`. Any key wakes from soft-off (via `zmk,soft-off-wakeup-sources` node). Each half wakes independently; BLE reconnects in ~2–3s. Wakeup keypress is not consumed but effectively swallowed by reconnect delay in practice. Planck (USB-only) has no sleep config.
- **No stuck layers:** all layer keys use `&mo` (momentary). Layers release the instant the key is released. No toggle or lock behaviors.

## Active Profiles

| Shield/Board | Form | Type | Custom shield? |
|---|---|---|---|
| `helix` | 5-row split 50% | Reference | No (upstream ZMK) |
| `helix_4row` | 4-row split 40% | Planck-like | Yes — `boards/shields/helix_4row/` |
| `planck` | 4-row one-piece 40% | — | No (upstream ZMK) |

Each profile has `config/<name>.conf` and `config/<name>.keymap`. Build targets are in `build.yaml`.

## Custom Shield Pattern

When a board needs a non-standard matrix (e.g. `helix_4row` which physically removes the 5th row), create a custom shield under `boards/shields/<name>/` containing:
- `Kconfig.shield` — registers shield names with the build system
- `<name>.dtsi` — defines `zmk,matrix-transform` and `kscan` row-gpios
- `<name>_left.overlay` / `<name>_right.overlay` — define col-gpios per half

Upstream shields (helix, planck) are provided by ZMK; only their `config/<name>.conf` and `config/<name>.keymap` live in this repo.

## Workflow Rules

1. Any new build target must be added to `build.yaml` (this drives the GitHub Actions matrix).
2. When modifying any keymap layer, audit parity across all active profiles and port changes consistently.
3. Split wireless boards use nice!nano. Board IDs use ZMK's Zephyr 4.1 variant syntax:
   - nice!nano v2 (default): `nice_nano//zmk`
   - nice!nano v1: `nice_nano@1//zmk`
   - Planck: `planck//zmk`
   Standard `.conf` settings:
   ```properties
   CONFIG_BT_CTLR_TX_PWR_PLUS_8=y
   CONFIG_USB_HID_POLL_INTERVAL_MS=1
   ```
